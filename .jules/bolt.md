## 2025-02-13 - Batched Database & KV Removals
**Learning:** Sequential DB (`localDB`) and KV store (`appKV`) deletion loops can cause significant bottlenecking during bulk operations like `deleteUser`. While the exact magnitude varies heavily depending on the JS engine (V8 vs JavaScriptCore) and specific environment (Web vs Tauri), performing independent I/O asynchronously via `Promise.all` yields substantial, measurable throughput improvements. Moreover, scratch files and benchmark scripts must be explicitly deleted and never included in the final pull request or pre-commit verification stage.
**Action:** When performing independent IndexedDB, Key-Value, or File Storage I/O across loops, wrap the promises in an array and resolve them concurrently with `Promise.all` rather than using sequential `for...of` iteration. Remember to explicitly clean up benchmark files after profiling.
